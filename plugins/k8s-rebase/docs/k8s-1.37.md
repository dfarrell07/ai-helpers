# Kubernetes 1.37 / OpenShift 5.1 rebase notes

Source snapshot: 2026-09-24. These are preparation findings, not a claim that
every consumer or runtime has passed a 1.37 rebase. Recheck branch heads and
PR status before using temporary dependencies.

The current matrix target is **1.37.1**, released on 2026-09-23. Earlier
trials used 1.37.0; preserve their version and source identity when comparing
results. The release overview still listed 1.37.0 during this check, while the
[published release](https://github.com/kubernetes/kubernetes/releases/tag/v1.37.1)
and [staging-module metadata](https://proxy.golang.org/k8s.io/api/@v/v0.37.1.info)
confirmed 1.37.1. Check actual tags and module availability when summaries lag.

The [1.37.1 patch notes](https://github.com/kubernetes/kubernetes/blob/release-1.37/CHANGELOG/CHANGELOG-1.37.md#v1371)
report release builds using Go 1.26.8; that is distinct from the module minimum
below. They include Windows kube-proxy handling of HNS load balancers without
port mappings, DRA selector/overflow fixes, kubeadm DNS configuration handling,
and a PodCertificate conformance-test adjustment for unprivileged environments.
These do not establish that a consumer's local tests or cluster tests pass.

Go does not necessarily change in this rebase: the 1.36.2, 1.37.0, and 1.37.1
modules require Go 1.26.0. Keep a repository's higher minimum/toolchain
requirement, such as upstream OVN's Go 1.26.3. Check OpenShift CI image
streams independently of Go changes; a correct Go version can still point
at the previous OpenShift stream. Verify image existence before changing
tags or node-image digests.

Attribute Go-reference findings against the base **Go directive**, not any
change to go.mod. A pre-existing Go 1.25 Dockerfile was already inconsistent
with a Go 1.26 baseline; a dependency-only 1.37 rebase does not introduce it.
Conversely, an actual Go directive increase can invalidate an untouched
reference. The Go-version gate has regression coverage for both cases.

| openshift/controller-runtime-common | `e1187ec555fc` | Check its target branch for compatibility fixes |

`build-machinery-go` has no release-5.1 branch in this snapshot; its existing
fallback resolves `@latest` and checks Kubernetes requirements. Do not use
`@latest`, `main`, or another release branch as a general OpenShift fallback.

Go `require` versions are [minimums](https://go.dev/ref/mod#minimal-version-selection).
Step 1 accepts older core Kubernetes floors from the explicitly selected
OpenShift branch, rejects newer minors and unverifiable versions, and records
that builds must establish compatibility. The controller-tools pairing and
build-machinery-go `@latest` fallback retain exact-minor checks. Final module
pins must still match the requested target; this is not permission to leave
resolved modules at 1.36 or to accept 1.38 dependencies.

An isolated graph probe with these four OpenShift modules and explicit
`k8s.io/api`, `apimachinery`, and `client-go` v0.37.0 resolved successfully
without lowering those pins. That proves dependency resolution only. The
unmerged library-go work contains actual source compatibility changes.

## Migration checks that need reasoning

- **Authorization:** library-go's pending rebase adapts `union.New` to named
  authorizers and its error return, and adds conditions-aware authorization
  methods. Inspect the [library-go diff](https://github.com/openshift/library-go/pull/2408/files)
  and the pinned Kubernetes interfaces. Preserve authorizer ordering, errors,
  and authorization behavior when repairing consumers. A real compiler probe
  of `controllercmd` at `975a098b90da`, with all ten resolved staging modules
  at v0.37.0, fails at `builder.go:327`, `:330`, and `:331` on those signatures.
  This is a confirmed consumer build blocker, not merely an older module floor.
- **Removed server gates:** `AuthorizeWithSelectors` is removed, which affects
  library-go's manifest client. Other removals include `APIServerTracing`,
  `AnonymousAuthConfigurableEndpoints`, `BtreeWatchCache`,
  `ConsistentListFromCache`, `ResilientWatchCacheInitialization`,
  `RetryGenerateName`, `StreamingCollectionEncodingToJSON`,
  `StreamingCollectionEncodingToProtobuf`, and
  `StructuredAuthenticationConfiguration`. Check actual use against
  [tagged apiserver features](https://github.com/kubernetes/apiserver/blob/v0.37.0/pkg/features/kube_features.go).
  Do not add removed server gates to the client fake-test `GATE_DEPS` map.
- **Code generation:** API generation handles an error returned by
  `ParseDocumentationFrom`; client regeneration changes discovery interfaces
  to `discovery.DiscoveryInterfaces` and typed informer supersets. Custom
  clientset mocks may need regeneration; deprecated v2beta1 discovery helpers
  are removed. Compare against the [tagged discovery source](https://github.com/kubernetes/client-go/blob/v0.37.0/discovery/discovery_client.go).
  The [client PR](https://github.com/openshift/client-go/pull/392/files)
  also accounts for a generated `tags/` path that a broad ignore rule can
  discard. After generation, inspect ignored/untracked output as well as
  tracked diffs; successful generator exit is not proof every output was kept.
- **Controller-runtime:** v0.25 broadens the event-recorder interface with
  annotated events, which can affect manager mocks. Its experimental
  read-your-writes support is opt-in, not a required rebase change. See the
  [runtime release notes](https://github.com/kubernetes-sigs/controller-runtime/releases/tag/v0.25.0).
- **Client feature gates:** `client-go/features/known_features.go` is unchanged
  between [v0.36.2](https://github.com/kubernetes/client-go/blob/v0.36.2/features/known_features.go)
  and [v0.37.0](https://github.com/kubernetes/client-go/blob/v0.37.0/features/known_features.go).
  `WatchListClient` remains the existing test-fake concern. `InOrderInformers`
  is already locked on. Do not add a speculative 1.37 autofix gate.
- **Temporary dependency fixes:** inspect the current plumbing PRs when builds
  fail inside their packages. Pin a reviewed fix to a commit, add its removal
  TODO, and apply required replacements in every affected consumer module.
  Replacements in a dependency's go.mod do not propagate to consumers. The
  library-go WIP itself uses API/client replacements; copying only its module
  version may be insufficient. Never hand-edit vendor or silently promote
  WIP forks to shipped dependencies.

Read the [Kubernetes changelog](https://github.com/kubernetes/kubernetes/blob/v1.37.0/CHANGELOG/CHANGELOG-1.37.md)
for the packages actually used by the target repository. A release highlight
or planned KEP is not evidence that a specific API was removed in the tag.

For cluster-facing tests, also check the
[1.37 upgrade notes](https://github.com/kubernetes/kubernetes/blob/release-1.37/CHANGELOG/CHANGELOG-1.37.md#urgent-upgrade-notes):
SELinux volume-labeling behavior changes, scheduling `v1alpha2` is removed,
and kubelet's zero `eventRecordQPS` now means unlimited. Kubeadm `v1beta3` is
removed; existing KIND templates must use a supported configuration API.
Apply these checks where the repository configures or consumes those surfaces;
a dependency rebase does not authorize changing unrelated cluster policy.

## Test preparation

[config-1.37.yaml](../test/config-1.37.yaml) pins six starting commits, each
still on Kubernetes 1.36.2, targeting 1.37.1. OpenShift consumers use release-5.1; upstream OVN
and MCP use their default branches. These are exploratory cases, with no
invented known-good 1.37 reference. The existing 16 pattern-retention eval
cases remain unchanged.

Start one full-skill test in a disposable clone:

```bash
make test repo=openshift/multus-cni version=1.37 spec=none
make watch version=1.37
make results repo=openshift/multus-cni version=1.37
```

Here `version=1.37` selects the matrix config's pinned 1.37.1 target. Direct
skill invocation still normalizes `1.37` to `1.37.0`; request `1.37.1`
explicitly to use this patch outside the harness.

The background harness requires workspace trust as documented in
[testing prerequisites](../evals/README.md). Use a separate clone for each
concurrent case. For development trials, the synchronous
`evals/scripts/run-rebase.sh` also snapshots the current plugin so a worker
cannot modify the source under test. Put its working directory and
`EVAL_REPO_DIR` under `.work/k8s-1.37/`, and record the plugin commit plus any
uncommitted patch alongside the run artifacts.

Review exact target pins in every module, build/vet/test and generator
outcomes, all gate reports, independent review, the final PR command, and
cleanup. Record unavailable dependencies or cluster-only checks as unresolved.
Inspect actual CI modes and variable consumers: MCP has separate
[offline and live-cluster e2e modes](https://github.com/ovn-kubernetes/ovn-kubernetes-mcp/blob/858f54cf9af4470909348f0f99bef2c705d12ca5/.github/workflows/e2e.yml).
Its [Makefile](https://github.com/ovn-kubernetes/ovn-kubernetes-mcp/blob/858f54cf9af4470909348f0f99bef2c705d12ca5/Makefile)
`K8S_VERSION` selects kubectl, while its
[KIND deployment](https://github.com/ovn-kubernetes/ovn-kubernetes-mcp/blob/858f54cf9af4470909348f0f99bef2c705d12ca5/hack/deploy-kind-ovnk.sh)
delegates to a separately cloned OVN repository. An e2e directory does not
itself establish a cluster requirement, nor does a version variable's name
establish which image it controls.
Only set a 1.37 `known_good` reference after independent review; until then
court/overall qualification remains pending even if an individual run passes.
Do not label a forced advancement or infrastructure fallback successful.
